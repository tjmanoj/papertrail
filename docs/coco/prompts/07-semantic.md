PHASE 4 — the governed semantic layer. Read CORTEX.md, docs/data-model.md
(section 2 especially) and docs/architecture.md first.

This is the core of the product. Everything else depends on it being right.

GOLD is built and healthy: DIM_COUNTERPARTY (809), DIM_ACCOUNT (1,497),
FACT_TRANSACTION (240,798), FACT_ALERT (219), FACT_CASE (93), plus CURATED
including ENTITY_LINK for beneficial-ownership resolution.

Use CoCo's native semantic view tooling, not hand-written DDL:
`cortex agent-studio sv-generate` to scaffold from the GOLD schema, then refine
the YAML deliberately, then `sv-write` and `sv-deploy`. Best practice is
scaffold-then-refine; do not ship the raw autogenerated spec.

Build it as follows.

1. A semantic view named PAPERTRAIL.GOLD.PAPERTRAIL_SEMANTIC covering the GOLD
   facts and dimensions, with relationships declared.

2. Implement ALL SEVEN governed metrics from docs/data-model.md section 2,
   exactly to the "intended SQL semantics" each one specifies:
     total_suspicious_transaction_volume_usd
     counterparty_exposure_usd
     alert_closure_rate
     sar_filing_rate
     structuring_indicator_score
     days_to_case_resolution
     high_risk_counterparty_count
   For each metric, the description must state the governance decision it
   encodes - which date basis, whether reversals and pending are included,
   cohort vs snapshot, how the denominator is scoped. A compliance officer
   reading the description should understand WHY the number is what it is.
   This text is the product, not documentation.

3. Business-facing names and synonyms throughout. A compliance analyst asks
   about "suspicious volume", "exposure", "SAR rate", "structuring" - make sure
   those land on the right metric.

4. VERIFIED QUERIES. Add at least 8, covering each of the seven metrics plus one
   multi-metric question. Each is a natural-language question paired with the
   correct SQL. These materially raise text-to-SQL accuracy and the session
   speakers called them crucial, so treat them as first-class.

5. Deploy the semantic view and confirm it exists in Snowflake.

6. VALIDATE against natural language. Run these questions through Cortex Analyst
   against the deployed view and report, for EACH: the question, the SQL Analyst
   generated, the answer, and whether the SQL honoured the governed semantics
   (e.g. did it correctly exclude reversals, use the right date basis):
     a) What was our total suspicious transaction volume last quarter?
     b) Which counterparties have the highest exposure?
     c) What is our alert closure rate this year?
     d) How many high risk counterparties do we have in Singapore?
     e) What share of cases resulted in a SAR filing?
   Be honest where Analyst got it wrong or ignored a governance rule - I need to
   know the real accuracy, not a flattering summary.

7. Save the YAML into semantic/ and the deploy SQL into sql/06-semantic.sql
   (idempotent). Suspend PAPERTRAIL_WH when done.

Report: what was created, the metric list with its governance decision, the
verified queries added, and the full validation results from step 6.
